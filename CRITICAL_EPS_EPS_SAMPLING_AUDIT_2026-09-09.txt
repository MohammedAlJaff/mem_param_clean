SAMPLING CONTRACT AND EQUATIONS

The convention is t=0 for noise and t=1 for data:
  z_t = t*x + (1-t)*eps
  v = x - eps

Configuration -> GDFM attributes -> model.sample -> Euler/Heun -> predict
-> model.convert(source=model.prediction_space, target="v") -> solver update
-> final state -> optional conversion to x.

Prediction space states what the network emits. Loss space states which
target the objective compares against. eps/eps uses direct unit-MSE noise
prediction. Since source==target, training conversion returns the prediction
unchanged; training safe division does not modify this diagonal objective.

Exact sampling velocities:
  x prediction:   v_hat = (x_hat-z_t)/(1-t)
  eps prediction: v_hat = (z_t-eps_hat)/t
  v prediction:   v_hat = network output

Heun evaluates velocity at the current state/time, forms an Euler trial state,
evaluates velocity at that trial state and the next time, then averages both.
Both stages convert from the model's prediction space.

At fixed state, delta_v = -delta_eps/t. At t=0.01 the amplification is 100.
For the same prediction expressed in velocity units, squared epsilon error is
t^2 times squared velocity error. A small early-time epsilon error can hide a
substantial velocity error. For example, eps_hat=z gives zero velocity, although
its epsilon error can be small near the noise endpoint.

The logged loss averages a training batch over random times. It does not
measure early-time velocity accuracy or accuracy along generated trajectories.
Pairwise training-target error also includes conditional target variance;
do not automatically equate it with error against the optimal marginal field.

The zero-initialized network gives eps_hat=0. Exact integration satisfies
dz/dt=z/t. With start=0.01 and output=x_1, the expected result is z_init/0.01.
Saved step-zero samples match it with RMSE 2.9974661e-5 and maximum absolute
error 0.0003051758. This supports parameterization handling through the actual
monitoring path, but does not establish trained-field accuracy.

Safe division reconstructs x first, then forms velocity:
  v_hat = (z-(1-t)*eps_hat)/max(t,c) - eps_hat

This is not (z-eps_hat)/max(t,c). Below c it changes the field even for a perfect
paired epsilon prediction: v_hat=(t/c)*x-eps. At t=0.01 and c=0.05, sensitivity
to epsilon error is (1-t)/c+1 = 20.8 instead of 100.

Changing the floor alone does nothing while use_safe_division=False.
Enabling floor=0.01 has essentially no effect on eps sampling in [0.01,0.99].
A 0.05 floor is meaningful, but success under it is a clamped-sampling result,
not evidence that strict exact sampling works.

output=x_t_max returns the integrated state at end_time. output=x_1 makes one
additional prediction and converts that state to a clean-data estimate;
it does not integrate the ODE all the way to t=1.

   Endpoints changed; assess this as a separate protocol factor.

   and precision before cross-device comparisons.
